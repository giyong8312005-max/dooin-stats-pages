# 철거업체 지역×물건별 홈페이지 대량 생성 가이드

> 두인경매 「전국 1,300개 경매 통계 페이지」(이 저장소)를 만든 방식을,
> **철거업체가 '강남구 주택 철거' 같은 소형 키워드를 노리는 홈페이지**에 그대로 응용하는 안내서입니다.
> Claude Code를 쓸 줄만 알면 코딩을 몰라도 따라할 수 있게 썼습니다.

---

## 0. 전체 그림 — 무엇을 만드는 건가

이 방식의 이름은 **프로그래매틱 SEO(Programmatic SEO)** 입니다.
페이지를 한 장씩 손으로 만드는 대신,

```
데이터 파일(지역 목록 + 서비스 목록 + 지역별 팩트)
        │
        ▼
생성기 스크립트(Python + Jinja2 템플릿)   ← Claude Code가 만들어 줌
        │
        ▼
정적 HTML 페이지 수백 개 (지역 × 서비스 조합마다 1장)
        │
        ▼
무료 호스팅 배포(GitHub Pages 또는 Netlify)
        │
        ▼
네이버 서치어드바이저 + 구글 서치콘솔에 사이트맵 제출
```

두인경매 프로젝트는 이 파이프라인으로 `서울/강동구/아파트` 처럼
**269개 지역 × 5개 물건유형 = 1,300여 개** 페이지를 자동 생성했습니다.
철거 사이트는 크롤러(데이터 수집기)가 필요 없어서 오히려 **더 간단**합니다.
데이터를 직접 파일에 적어 넣으면 되기 때문입니다.

### 두인 프로젝트와 같은 점 / 다른 점

| 항목 | 두인경매 통계 (이 저장소) | 철거업체 사이트 |
|---|---|---|
| 페이지 축 | 지역 × 물건유형 (아파트/빌라/상가/토지/주택) | 지역 × 철거 종류 (주택/빌라/상가내부/공장·창고 등) |
| 데이터 출처 | 크롤러가 매주 자동 수집 | 직접 작성 + 공공데이터 (수집기 불필요) |
| 갱신 주기 | 매주 (GitHub Actions) | 사실상 고정 (가끔 수동 갱신) |
| 목표 행동 | 알림 신청 | **전화 걸기 / 견적 문의** |
| 페이지 수 | 1,300여 개 | 실제 영업권역만: 보통 50~300개로 시작 |

## 1. 시작하기 전에 — 반드시 알아야 할 3가지

### ① 전국 페이지를 다 만들지 마세요

실제로 출동 못 하는 지역의 페이지는 만들지 않는 게 좋습니다.

- 네이버·구글 모두 "내용이 거의 같은 페이지 수천 장"을 **유사문서/스팸으로 묶어서** 하나만 노출하거나 아예 노출을 내립니다.
- 서비스 불가능한 지역에서 전화가 오면 응대 낭비이고, "OO구 철거 전문"이라고 써놓고 실제로는 안 가는 건 허위·과장 표시 문제가 될 수 있습니다.

**권장:** 실제 영업권역(예: 서울 25개 구 + 인접 경기 10개 시) × 서비스 6~8종 = 200~300페이지 정도로 시작하고, 반응을 보며 넓히세요.

### ② 페이지마다 "정말 다른 내용"이 30% 이상 들어가야 합니다

지역명만 바꿔치기한 페이지는 네이버 유사문서 필터에 걸립니다. 이 저장소가 1,300페이지를 다 노출시킬 수 있었던 이유는 **페이지마다 실제 데이터(그 지역의 진행 물건 수, 낙찰가율, 물건 목록)가 달랐기** 때문입니다. 철거 사이트도 지역마다 다른 실데이터를 넣어야 합니다. (방법은 4단계에서.)

### ③ 네이버에서의 현실적인 기대치

'강남구 주택 철거'를 네이버에서 검색하면 위에서부터 파워링크(광고) → 플레이스 → 블로그/카페 → **웹사이트 영역** 순으로 나옵니다. 이 전략이 먹는 자리는 **웹사이트(웹문서) 영역**입니다. 그래서 병행하면 효과가 커집니다:

- **네이버 스마트플레이스** 등록 (무료) — 지도/플레이스 영역
- 시공 사례 **블로그** 포스팅 — 블로그 영역
- 이 가이드의 지역×서비스 페이지 — 웹사이트 영역

## 2. 준비물

1. **GitHub 계정** (무료) — 코드 저장 + 무료 호스팅(GitHub Pages)
2. **Claude Code** — 코드는 전부 이게 짜 줍니다
3. **도메인 1개** (연 1~2만 원, 예: `OO철거.kr` 또는 `oo-chulgeo.co.kr`) — 무료 주소(`xxx.github.io`)보다 신뢰도·노출에 유리. 필수는 아니지만 강력 권장
4. **업체 실제 정보** — 상호, 대표번호, 사업자등록번호, 주소, 보유 장비, 시공 사진 (사진은 페이지 신뢰도에 매우 중요)
5. **네이버 서치어드바이저 계정** (searchadvisor.naver.com, 무료)
6. **구글 서치콘솔 계정** (search.google.com/search-console, 무료)

---## 3. 1단계 — 키워드 매트릭스 설계

엑셀이나 메모장에 두 개의 목록을 만듭니다.

**지역 축 (실제 영업권역만):**
```
서울: 강남구, 서초구, 송파구, 강동구, ... (25개 구)
경기: 성남시, 하남시, 광주시, 용인시, ... (실제 가는 곳만)
```

**서비스 축 (실제 하는 공사만):**
```
주택 철거          → "강남구 주택 철거", "강남구 단독주택 철거"
빌라·다세대 철거    → "강남구 빌라 철거"
상가 내부 철거      → "강남구 상가 철거", "강남구 원상복구"
사무실 원상복구     → "강남구 사무실 철거"
공장·창고 철거      → "하남시 공장 철거", "하남시 창고 철거"
조립식·판넬 철거    → "광주시 조립식건물 철거"
비닐하우스·잔재물   → (교외 지역만)
석면 철거          → 석면해체 등록업체일 때만! (아니면 절대 넣지 말 것)
```

포인트:
- 서비스마다 **묶어서 잡을 연관 키워드**를 함께 적어두면 페이지 제목·본문에 자연스럽게 녹일 수 있습니다.
- 도심 구에는 비닐하우스 페이지를 안 만들고, 교외 시에는 상가 원상복구 비중을 낮추는 식으로 **지역마다 서비스 조합을 다르게** 하면 그 자체가 차별화가 됩니다.

## 4. 2단계 — 데이터 파일 만들기 (차별화의 핵심)

저장소에 데이터 파일 3개를 둡니다. (Claude Code에게 틀을 만들어 달라고 하면 됩니다)

**`data/regions.json`** — 지역 목록 + 영문 슬러그(주소용)
```json
[
  {"sido": "서울", "sido_slug": "seoul", "name": "강남구", "slug": "gangnam-gu"},
  {"sido": "경기", "sido_slug": "gyeonggi", "name": "하남시", "slug": "hanam-si"}
]
```

**`data/services.json`** — 서비스 목록 + 어떤 지역 유형에 만들지
```json
[
  {"key": "house", "ko": "주택 철거", "keywords": ["단독주택 철거", "구옥 철거"], "urban": true, "rural": true},
  {"key": "greenhouse", "ko": "비닐하우스 철거", "keywords": ["하우스 철거"], "urban": false, "rural": true}
]
```

**`data/region_facts.json`** — ★ 페이지를 서로 다르게 만들어 주는 지역별 실데이터
```json
{
  "gangnam-gu": {
    "노후주택_비율": "30년 이상 단독·다가구 비율 41%",
    "특징": "재건축 대기 단독주택 밀집(개포·일원), 상가 원상복구 수요 많음",
    "관할": "강남구청 건축과 02-3423-xxxx",
    "시공사례": ["2025.11 논현동 2층 단독주택 철거 (연면적 180㎡, 4일 소요)"],
    "주의사항": "이면도로 협소 구간 많아 소형 장비 병행 필요"
  }
}
```

### 지역별 실데이터를 어디서 구하나 (전부 무료 공공데이터)

- **공공데이터포털 (data.go.kr)** / **건축데이터 민간개방 (open.eais.go.kr)**: 건축물대장 — 지역별 노후 건축물(30년 이상) 동수·비율을 뽑을 수 있음 → "강동구에는 30년 이상 단독주택이 약 N동" 같은 문장이 페이지마다 달라짐
- **건축물생애이력관리시스템 (blcm.go.kr)**: 해체공사(철거) 허가·신고 통계
- **각 구청 고시·공고**: 재건축·재개발 구역 지정 현황 → "OO동 재건축 예정 구역" 언급
- **자기 시공 실적**: 지역별로 나눠 적기 — 이게 제일 강력한 차별화

> 이 데이터 수집 자체도 Claude Code에게 시킬 수 있습니다:
> "공공데이터포털에서 건축물대장 API 키를 발급받았어. 서울 25개 구별로 30년 이상 단독주택 동수를 집계해서 region_facts.json에 채워줘."

## 5. 3단계 — 페이지에 반드시 들어가야 할 것 (SEO 체크리스트)

이 저장소의 `app/templates/region_type.html`과 `app/generator.py`가 실제 예시입니다. 철거 페이지 한 장(`/seoul/gangnam-gu/house/`)에 들어갈 것:

**검색엔진용 (머리 부분)**
- [ ] `<title>`: `강남구 주택 철거 | 무료 견적·당일 방문 - OO철거` (키워드가 맨 앞, 32자 내외)
- [ ] `<meta name="description">`: 지역별 숫자가 들어간 1~2문장 (예: "강남구 단독·다가구 철거 전문. 논현동 등 시공 사례 N건, 해체신고 대행 포함 무료 견적.")
- [ ] `<link rel="canonical">`: 페이지 자기 자신의 주소
- [ ] JSON-LD 구조화 데이터 3종: `LocalBusiness`(상호·전화·지역) + `Service`(철거 종류) + `FAQPage`(아래 FAQ와 짝) + `BreadcrumbList`
- [ ] `sitemap.xml`, `robots.txt` 자동 생성 (생성기가 페이지 목록으로 만들어 줌)

**사람용 (본문) — 위에서부터**
1. 제목(H1): "강남구 주택 철거" + 한 줄 요약
2. **전화 버튼**(화면에 항상 떠 있게) + 간단 견적 문의 폼
3. 지역 맞춤 문단: region_facts의 데이터로 자동 조립 ("강남구는 재건축 대기 단독주택이 많아…")
4. 이 지역 시공 사례 (사진 + 규모 + 소요일)
5. 진행 절차 (해체신고/허가 → 석면조사 → 철거 → 폐기물 처리 → 멸실신고) — 공통 내용이지만 지역 관할 기관명은 지역별로
6. 가격이 갈리는 요인 (평수, 층수, 구조, 진입로, 석면 유무) — 확정 가격표보다는 "요인 + 무료 견적" 방식이 안전
7. FAQ 4~6개 — 최소 2개는 지역 맞춤 질문 ("강남구 이면도로 좁은 곳도 가능한가요?")
8. **내부 링크**: ① 같은 구의 다른 서비스 (강남구 빌라 철거, 강남구 상가 철거…) ② 인접 구의 같은 서비스 (서초구 주택 철거, 송파구 주택 철거…) ③ 상위 허브(서울 철거)로 가는 경로표시줄
9. 회사 정보 푸터: 상호·대표·사업자번호·주소·건설업 등록번호(비계구조물해체 면허 등 보유 시)

**사이트 전체 구조 (3층):**
```
홈(/)  →  시·도 허브(/seoul/)  →  지역×서비스 페이지(/seoul/gangnam-gu/house/)
```
이 3층 구조 + 인접지역 링크 덕분에 검색로봇이 모든 페이지를 타고 다닐 수 있습니다. 두인 프로젝트와 완전히 같은 구조입니다.

## 6. 4단계 — Claude Code에게 시키기 (복붙용 프롬프트)

새 GitHub 저장소를 만들고 Claude Code를 연 다음, 아래를 자기 상황에 맞게 고쳐서 붙여넣으세요.

```
철거업체 홈페이지를 프로그래매틱 SEO 방식으로 만들어줘.

[회사 정보]
- 상호: OO철거산업 / 대표번호: 010-xxxx-xxxx / 사업자: 123-45-67890
- 주소: 서울 강동구 ... / 영업권역: 서울 전체 25개 구 + 하남·구리·성남
- 서비스: 주택철거, 빌라철거, 상가 내부철거·원상복구, 공장·창고 철거, 조립식건물 철거
- (석면 해체 면허 없음 → 석면 페이지는 만들지 마)

[만들 것]
1. Python + Jinja2 정적 사이트 생성기. 구조는:
   data/regions.json (지역+영문슬러그), data/services.json, data/region_facts.json
   → generator.py 가 site/ 폴더에 HTML 생성
2. URL 구조: /{시도슬러그}/{시군구슬러그}/{서비스키}/index.html
   + 시도 허브 페이지 + 홈페이지 (3층 구조, 경로표시줄 포함)
3. 페이지마다: 키워드 앞세운 title, meta description, canonical,
   JSON-LD(LocalBusiness+Service+FAQPage+BreadcrumbList),
   상시 노출 전화 버튼(tel: 링크), 견적 문의 폼,
   같은 지역 다른 서비스 링크 + 인접 지역 같은 서비스 링크
4. region_facts.json 의 지역별 데이터(노후주택 통계, 시공사례, 지역 특징)를
   본문 문단과 FAQ에 반영해서 페이지마다 내용이 실제로 다르게 만들어줘.
   facts 가 빈 지역은 페이지를 만들지 말고 목록으로 알려줘.
5. sitemap.xml, robots.txt 자동 생성. 모바일 우선 반응형 디자인.
6. GitHub Actions로 main에 푸시하면 GitHub Pages에 자동 배포되게 해줘.

일단 서울 3개 구(강남·서초·송파) × 서비스 3개만 샘플로 만들어서 보여줘.
확인 후에 전체로 확장할게.
```

**꼭 이 순서로:** 샘플 9페이지 먼저 → 눈으로 확인·수정 → 전체 생성. 처음부터 300장을 뽑으면 잘못된 문구가 300장에 복제됩니다.

## 7. 5단계 — 배포와 검색 등록

1. **배포**: GitHub Pages(무료, 설정 몇 번의 클릭) 또는 Netlify(이 저장소가 쓰는 방식). Claude Code에게 "GitHub Pages 배포 설정해줘" 하면 됩니다. 커스텀 도메인 연결도 시키면 해 줍니다.
2. **네이버 서치어드바이저** (searchadvisor.naver.com):
   - 사이트 등록 → 소유확인 (HTML 파일 업로드 방식 — 생성기가 파일을 넣게 하면 됨. 이 저장소도 `naver11bd....html`을 자동으로 넣습니다)
   - 요청 → **사이트맵 제출**: `https://내도메인/sitemap.xml`
   - 요청 → 웹 페이지 수집: 홈과 허브 페이지 몇 개는 수동으로 수집 요청
3. **구글 서치콘솔**: 같은 방식으로 등록 + 사이트맵 제출
4. **네이버 스마트플레이스** 등록 (별도, smartplace.naver.com) — 플레이스 영역은 이 사이트와 별개로 잡히므로 꼭 병행

노출까지 보통 수 주가 걸립니다. 서치어드바이저의 "수집 현황 / 색인 현황" 그래프가 올라가는지 매주 확인하세요.

## 8. 운영 — 만들고 나서 할 일

- **전환 추적**: 전화 버튼 클릭을 측정 (네이버 애널리틱스 또는 GA4 이벤트 — Claude Code에게 "전화 버튼 클릭 이벤트 심어줘")
- **순위 확인**: 대표 키워드 20~30개를 정해 매주 네이버에서 순위 기록
- **콘텐츠 갱신**: 공사 끝날 때마다 해당 지역 페이지의 시공 사례에 1건 추가 — 갱신되는 페이지가 순위가 오릅니다. region_facts.json에 한 줄 추가하고 재생성·재배포하면 끝
- **확장**: 색인·유입이 확인된 뒤에 인접 지역, 세부 키워드(동 단위는 비추천 — 너무 얇아짐)로 넓히기

## 9. 하지 말아야 할 것

1. **지역명만 바꾼 복사 페이지 대량 생산** — 유사문서로 묶여 통째로 노출이 죽습니다. 이 방식의 성패는 "페이지 수"가 아니라 "페이지별 실데이터"에 있습니다.
2. **가 본 적 없는 지역에 "OO구 지사/전문" 표기** — 허위·과장 표시. 영업권역은 "출장 가능 지역"으로 정직하게.
3. **없는 면허 서비스 페이지** (석면 해체 등) — 법 위반 소지.
4. **남의 시공 사진 도용** — 저작권 + 신뢰도 문제. 사진이 부족하면 없는 대로.
5. **확정 가격 남발** — 철거비는 변수가 많아 확정가 표기는 분쟁의 씨앗. "요인 안내 + 무료 견적"으로.
6. **트래픽 조작, 자동 클릭** — 네이버 어뷰징 제재 대상.
